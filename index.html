A Raspberry Pi that boosts… boots directly into NeXTSTEP

Previously starts straight into a NeXT machine under the Previous emulator. There is no desktop behind it, no login to get past, and nothing on the screen but the grey NeXT panel.

  • Raspberry Pi 4 or 5
  • Raspberry Pi OS Lite, 64 bit
  • NeXTSTEP 2.2 to OPENSTEP 4.2
Terminal
$ curl -fsSL https://previous.li/install.sh | bash

Run it as the user the machine will belong to, not under sudo. It asks for your password once and says when it is done where the admin answers.

What it is

The shortest way to get NeXTSTEP up and running on your Raspberry Pi

The Pi merges into a NeXT. Everything you would normally do directly in the Previous Settings on the Pi can now be done conveniently in a browser on another computer.

Nothing but NeXTSTEP

The emulator takes the first console at boot and keeps it. There is no desktop underneath and no console login to step past, so the machine is the thing it is pretending to be.

An admin that looks like it

You select NeXT machines, drives, and displays instead of entering values manually. You can switch between complete configurations using D&D. Change the values in the system configurations and save them as your own.

An installation that undoes itself

Every step of the install script writes down how to undo what it just did. Press Ctrl+C, or let a step fail, and it walks that record backwards. Whatever was on the machine before is left where it was.

The admin

It looks like the machine it configures

Nothing here is approximated. The icons are the original files out of a NeXTSTEP 3.3 disk image, the window buttons are cut pixel for pixel out of the running system, and every colour, edge and raster is measured off it.

Install

Three steps, and the second one is the line

You need a Raspberry Pi 4 or 5 and a card imaged with Raspberry Pi OS Lite, 64 bit, based on Debian 13. The script reads the architecture and the release and refuses an older one, because Previous needs SDL3 and no earlier release carries it.

  1. Reach the Pi

    Over SSH is the comfortable way, and it stays the way in afterwards: the emulator owns the screen once this is done.

  2. Paste the line and let it finish

    It installs the emulator from its own signed archive, fetches a preinstalled disk image, writes the configuration, installs the admin tool and hands the first console over. The image is NeXTSTEP 3.3, and the admin swaps it for any of the six afterwards.

    curl -fsSL https://previous.li/install.sh | bash

  3. Open the admin

    It answers at http://<your-pi>.local:8810 and asks you to choose a password the first time you open it. There is nothing to read off the Pi and nothing to copy.

Before you run it

What a line off the network is allowed to do

Read it first

The line fetches the installer from the repository it belongs to and runs it, so what you read there is what runs. That file reads nothing beside itself, and nothing in it happens until its last line calls main, which means a download cut short runs nothing at all.

Safe to run again

An existing disk image, an existing configuration and a startup entry that is already there are all left alone. Your own NeXTSTEP image in ~/nextstep is found and used instead of a download.

Ctrl+C leaves it as it was

An interrupt and a failing step both walk the record of changes backwards. Only this run's own changes are reversed, and a step that skipped itself has nothing to take back.
